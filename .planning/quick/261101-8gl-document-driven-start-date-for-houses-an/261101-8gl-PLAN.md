# Quick Task: 261101-8gl-document-driven-start-date-for-houses-an
# Document-Driven Start Date for Houses & Tenants and Remove Add-House Start Date Option

## Objective
Guarantee that the start date of every house and tenant is **always** determined by the earliest date (`MIN(primary_date)`) of the documents entered for it (remaining `null` / automatic until the first document is entered), and remove the manual Start Date option from the Create House (`#add-house-modal`) workflow.

## Context & Key Rules
1. **No Manual Start Date on House Creation**:
   - Remove `#add-house-tenant-date-input` and its label from `#add-house-modal` in `index.html`.
   - Remove auto-today initialization and date input reading from `openAddHouseModal()` / `handleAddHouseSubmit()` in `area-grid.js`, always posting `start_date: null`.
   - Enforce `StartDate = null` inside `CreateHouseAsync` so newly created houses and their initial resident tenants never store a synthetic start date prior to document entry.
2. **Strict `MIN(primary_date)` Synchronization Across All Document Lifecycle Operations**:
   - Introduce `SyncTenantStartDateAsync(conn, tx, tenantId)` in `FileOrganizerRepository` to keep `tenants.start_date` synchronized to `SELECT MIN(primary_date) FROM documents WHERE tenant_id = @TenantId AND is_timeline_visible = 1 AND primary_date IS NOT NULL AND primary_date != ''` — including clearing `tenants.start_date` to `NULL` when zero visible dated documents remain.
   - Invoke `SyncTenantStartDateAsync` across `AddManualDocumentAsync`, `UpdateDocumentAsync`, `DeleteDocumentAsync`, `BatchDeleteDocumentsAsync`, `BatchMoveDocumentsAsync`, `ExtractPagesAsync`, `DeletePagesAsync`, and `MergeDocumentsAsync`.
   - Enforce `minDocDate` priority in `BulkUpdateTenantsAsync` (symmetric to `maxDocDate` for past tenant end dates) and expose `FirstDocDate` (`first_doc_date`) on `TenantDto`.
3. **Frontend Resolution & Static Mode Parity**:
   - Add `resolveFirstDocDate` in `tenant-manager.js` so House Settings rows always prioritize `first_doc_date` / `MIN(primary_date)` from loaded timeline documents.
   - Replace the hardcoded `'2020-01-01'` fallback in `house-profile.js` static mode with the earliest document date per tenant (`null` when no documents exist).
   - Maintain 100% mirror parity between `src/HousingApplication.Web/wwwroot/` and `dist/win-x64/wwwroot/` and keep `.agents/` completely untouched in Git.

## Tasks
1. **Backend (`DTOs.cs`, `FileOrganizerRepository.cs`, `RepositoryTests.cs`, `ApiEndpointTests.cs`)**:
   - Add `FirstDocDate` (`first_doc_date`) to `TenantDto` and populate it in `GetTenantsAsync`.
   - Enforce `StartDate = null` in `CreateHouseAsync`, add `SyncTenantStartDateAsync` across all document write/move/delete/merge/page-split methods, and prioritize `minDocDate` in `BulkUpdateTenantsAsync`.
   - Add xUnit coverage in `RepositoryTests.cs` and `ApiEndpointTests.cs` for `CreateHouseAsync` null start date and full document insert/update/delete `StartDate` synchronization.
2. **Frontend UI (`index.html`, `area-grid.js`, `tenant-manager.js`, `house-profile.js`, `dist/win-x64/wwwroot/*`)**:
   - Remove `#add-house-tenant-date-input` from `#add-house-modal` in `index.html` and strip date-input logic from `area-grid.js`.
   - Add `resolveFirstDocDate` to `tenant-manager.js` and fix static-mode tenant start date derivation in `house-profile.js`.
   - Mirror all modified `wwwroot` files to `dist/win-x64/wwwroot/`.
